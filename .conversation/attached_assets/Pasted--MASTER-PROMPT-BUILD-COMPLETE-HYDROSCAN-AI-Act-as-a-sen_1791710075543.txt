# MASTER PROMPT — BUILD COMPLETE HYDROSCAN AI

Act as a senior full-stack developer, geospatial data scientist, machine-learning engineer, UI/UX designer, and technical mentor. Build a complete, functional, professional end-semester engineering project named:

**HydroScan AI: AI-Powered River Pollution Detection, Prediction and Environmental Intelligence System**

## 1. Project objective

Develop an environmental-intelligence web application that analyzes Sentinel-2 satellite imagery of a selected stretch of the Godavari River near Nashik, Maharashtra, India, to identify potential water regions, detect spectral anomalies, calculate preliminary environmental risk indicators, visualize results, and generate reports for further investigation.

This is a college engineering project. Prioritize real functionality, scientific credibility, a professional interface, and code that a student can understand and explain.

## 2. Mandatory technology stack

- Frontend: HTML5, CSS3, JavaScript, Bootstrap or a polished custom responsive design.
- Backend: Python and Flask.
- Image and geospatial processing: NumPy, Rasterio, Pillow, Matplotlib, and GeoPandas only where needed.
- Data analysis and machine learning: Pandas and scikit-learn where appropriate.
- Interactive maps: Leaflet with OpenStreetMap-compatible basemaps.
- Charts: Chart.js or Matplotlib.
- Reports: PDF generation using a suitable Python library.
- Data persistence: SQLite if persistent storage is required; avoid unnecessary database complexity.
- Development: VS Code, with a clearly documented Python virtual environment.

Do not use Streamlit. Do not require paid APIs, paid datasets, paid hosting, or a paid AI API. The core application must work locally without an external AI API key.

## 4. Required application pages

### A. Overview dashboard
- Professional dark navy, teal, white, and subtle green environmental-intelligence theme.
- Sidebar navigation, responsive layout, metric cards, charts, and recent analyses.
- Study-area description, data source, observation date, processing status, and last analysis time.
- Display only metrics calculated from actual available data.
- Distinguish measured, satellite-derived, estimated, and demonstration values.

### B. Satellite imagery explorer
- Upload or select compatible local Sentinel-2 band files.
- Display an RGB composite using the available red, green, and blue bands.
- Display NDWI when suitable green and near-infrared bands are available.
- Provide layer toggles, legends, image metadata, and download options.
- Handle different raster dimensions, missing files, nodata values, CRS information, and invalid inputs safely.
- Never silently resample data or misalign bands without documenting the operation.

### C. Water-region analysis
- Calculate NDWI using the formula (Green - NIR) / (Green + NIR), with safe handling of zero denominators and invalid pixels.
- Allow a configurable threshold and show how the threshold changes the candidate water mask.
- Provide raw and cleaned candidate masks with side-by-side comparisons.
- Include basic connected-component filtering or morphological cleaning where appropriate.
- Show pixel counts and valid-pixel coverage, but do not describe the mask as a verified river boundary unless independently validated.
- Clearly explain the limitations of NDWI, including confusion with shadows, land cover, turbidity, and other surface conditions.

### D. Spectral anomaly and preliminary risk analysis
- Identify unusual spectral patterns using defensible, transparent statistical methods.
- Where data supports it, calculate normalized band-based indicators and robust outlier scores.
- Explain which bands or indicators contributed to each flagged region.
- Provide configurable preliminary categories such as Low, Moderate, and High anomaly priority.
- Show the thresholds and reasoning behind each category.
- Include confidence or data-quality indicators where they can be justified.
- Do not call these categories confirmed water-quality measurements or verified pollution levels.
- Do not train a model on invented labels or report fabricated accuracy, precision, recall, or F1 scores.

### E. Interactive geographical map
- Display the study area and available georeferenced results on a Leaflet map.
- Overlay georeferenced raster results only when valid geographic transforms and coordinate reference systems are available.
- Show flagged locations with explanatory popups and priority labels.
- Do not invent latitude/longitude coordinates or exact pollution-source locations.
- If georeferencing is unavailable, show the image in pixel coordinates and explain the limitation.

### F. Historical comparison and trend analysis
- Allow comparisons between available dated satellite observations.
- Display trends only when at least two genuinely distinct, dated observations are available and are processed consistently.
- Explain when seasonal changes, clouds, sensor differences, or processing differences affect comparisons.
- If only one observation is available, show a clear message that historical trend analysis requires additional dates.

### G. Reports and exports
- Generate downloadable PDF analysis reports.
- Include study area, source-image metadata, observation date, RGB image, NDWI visualization, candidate water mask, anomaly results, charts, limitations, and suggested follow-up investigations.
- Export calculated tables to CSV.
- Include a unique report ID and report-generation timestamp.
- Never include fabricated measurements or unsupported conclusions.

### H. Analysis history
- Save analysis metadata and report records locally.
- Allow the user to reopen previous analyses and download their reports.
- Handle missing or deleted output files gracefully.

### I. Methodology and help
- Explain the full workflow from satellite bands to indicators, masks, anomaly flags, and reports.
- Include formulas, assumptions, a system architecture diagram, limitations, and future improvements.
- Add a beginner-friendly guide describing how to run the project and explain its modules during a college viva.
